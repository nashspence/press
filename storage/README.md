# Asset storage

Keep independent originals and retain all referenced B2 versions. Disable automatic expiry and byte transformations. During recovery or migration, preserve URLs and bytes for current manuscripts and past editions. Run the [integrity audit](../.github/workflows/audit-assets.yml) before retiring the old origin.

The local image uploader validates the original bytes, derives their SHA-256 object key, uploads an absent image, and verifies both B2 and the public gateway before printing a manuscript reference. Reusing an existing key verifies it without adding another image version. A conflicting or hidden object requires operator inspection. The uploader renews a small lease under `sha256/.leases/` on every use, including reuse, to protect an image before its manuscript is pushed. The public Worker serves only image keys and remains read-only.

## Local upload credentials

Use a standard B2 application key restricted to the asset bucket and the exact `sha256/` prefix, with `listFiles` and `writeFiles`. The same read/write application key may also serve hosted cleanup; extra capabilities granted by B2's access preset are accepted, but these tools never change bucket configuration or access another bucket/prefix. The upload client cannot invoke deletion, and the preview client cannot invoke writes. Upload needs no Cloudflare token or GitHub App. Keep credentials outside Git, in an owner-only regular file (mode 0600), using the names in [the credential template](credentials.env.example). The default private file is `.env.assets`, which Git ignores. An explicit `B2_ENV` selects another private file. Without a file, the same values can come from the process environment. The file is parsed as data, never executed as shell code. Consult `make help` for targets and arguments.

## Branch retirement and cleanup

Use [Retire branches and clean assets](../.github/workflows/maintain-assets.yml) on main to retire a feature branch. Close or merge every PR that uses it first. Review the branch tip and supply its full SHA. Retirement uses Git's compare-and-delete lease: if another push changes that tip, deletion fails. Main and the repository's default branch cannot be retired. The workflow records the requested branch and tip before collecting eligible assets. If cleanup fails after deletion, retry retirement with the same inputs or request a sweep; an already absent branch is a cleanup retry.

Cleanup retains every digest mentioned in main history, live branch tips, and open PR heads, including forks. This covers historical manuscript images, reviewed source snapshots, frozen proofs and all issued editions, including withdrawals. It deliberately recognizes digest tokens in prose and metadata too; some unneeded objects may therefore remain. Local scans also protect branch tips, index entries and nonignored working files, but hosted cleanup cannot see unpushed local work. An upload lease or image version younger than 30 days protects the whole object. Renew the lease by uploading again before resuming old unpushed work.

The collector previews eligible image and lease versions by default. An explicit sweep removes actual B2 versions and hide markers only for unreferenced objects outside the grace period. Unknown object names and unfinished uploads remain untouched. A failed or incomplete GitHub, Git or B2 inventory stops collection. Before deleting each object, the collector rescans references and requires its exact version inventory to remain unchanged. B2 deletion does not purge existing CDN copies. Pause uploads and source changes while applying cleanup: GitHub and B2 cannot provide a transaction across both services, and cross-client changes can still race the final checks. Main-history retention protects every image ever merged, so retiring a merged branch usually reclaims nothing.

The Make cleanup and retirement entry points dispatch this workflow through `gh`; they do not retrieve secret values. A weekly sweep shares the same serialized maintenance queue. Enable scheduled sweeps only after setup and a successful hosted preview by setting repository variable `PRESS_ASSET_MAINTENANCE_ENABLED` to `true`. Missed or failed runs leave excess storage and can be retried. Unreferenced uploads and assets removed from still-open branches are handled by later sweeps. Repository rules cannot govern branches in contributors' forks.

## Maintenance setup

Create a private GitHub App with only Contents write and the automatic Metadata read permission, no webhooks, and install it on this repository only. In the `press-assets` environment, configure variable `PRESS_ASSET_APP_CLIENT_ID` and secret `PRESS_ASSET_APP_PRIVATE_KEY` directly. Keep the release-policy App read-only. Cleanup requires `listFiles` and `deleteFiles` on the same single bucket and exact prefix; a shared B2 read/write application key is supported. Store all four B2 values from the credential template as environment secrets, including the bucket ID and name, so public job logs mask operational configuration too. Restrict environment deployment branches to the single branch `main`, without required reviewers if scheduled sweeps should run unattended. Never expose these credentials to PR code.

Disable automatic branch deletion after merge. The operator's policy plan/apply targets install a deletion-only ruleset for all branches with this App as its sole bypass actor. They require main's separate active deletion protection to have no bypass and leave it unchanged. The App therefore cannot delete main or bypass its publication checks. Keep feature branch updates available. The workflow checks out trusted main code, reads other branches only as Git data, creates a repository-scoped App token only for retirement, and revokes that token on completion. Branch deletion uses that token; inventory reads use the read-only workflow token.
