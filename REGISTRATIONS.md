# External identifiers and registration index — v1

`press` separates the *work*, its *individual official editions and formats*, the *author/imprint*, and any qualifying *serial publication*. Each can have identifiers issued by external registries. No identifiers are generated by this repository. **Do not enter an identifier unless it has actually been assigned or its registry record verified.** Validation here is offline: shape/check digits, scope, consistency and deterministic serialization, not existence or ownership.

## Scope and canonical locations

| Scope | Location | Keys allowed |
| --- | --- | --- |
| Evolving work | `works/<slug>/manuscript.md` front matter (`press.work.v2`) | `concept_doi`, `arxiv`, `openalex`, `wikidata` |
| Post-publication work index | `registrations/works/<slug>.json` | Same work keys, including IDs indexed after release |
| Specific edition / format | `registrations/editions/<slug>/vX.Y.Z.json` | `version_doi`, `arxiv_version`, `isbn_epub`, `isbn_pdf`, `isbn_print`, `oclc` |
| Author | `registrations/identities/author.json` | `orcid`, `isni`, `wikidata`, `openalex_author` |
| Imprint | `registrations/identities/imprint.json` | `isni`, `wikidata`, `openalex_publisher` |
| Qualifying continuing series | `registrations/series/<slug>.json` | `issn`, `issn_l`, `wikidata` |

Only registration records for **real existing registrations** should be added. All paths above are optional, but the required keys of any present record are mandatory. `registrations/README.md` is the only Markdown file permitted directly under this directory.

For each registration record, the root must be a JSON object with exactly the schema-specific required/optional keys described below; extra keys fail. All records use canonical JSON (UTF-8 NFC, sorted object keys, 2-space indentation, LF, final newline, no duplicate keys). Manuscript **authoring** remains YAML front matter; these JSON records are appendable external registration facts, not replacement manuscript metadata.

### Work index

Required fields: `schema: "press.work-registration.v1"`, `work` (existing slug), `identifiers` (nonempty mapping of work keys). A work ID in this index and in manuscript front matter must agree if duplicated. Adding newly discovered OpenAlex or Wikidata records here does **not** retroactively change a tagged edition.

### Edition registration

Required fields: `schema: "press.edition-registration.v1"`, `work`, `version`, `release_url`, `canonical_artifact`, `artifact_sha256`, `published_at`, `rights`. Optional field: `identifiers` (nonempty mapping if present).

- Path: `registrations/editions/<slug>/vX.Y.Z.json`. `work` and `version` must match the path and refer to a tracked manuscript.
- `release_url` must be a GitHub Release URL for the exact matching `works/<slug>/vX.Y.Z` tag in this repository. The URL is checked **syntactically** (not fetched).
- `canonical_artifact` is the attached authoritative file basename, ending `.html`, `.pdf`, `.epub` or `.md` (the preferred publishing format is HTML). `artifact_sha256` is 64 lowercase hex digits of its bytes; the current offline checker does not download the asset to recompute this digest.
- `published_at` is a valid UTC timestamp, `YYYY-MM-DDTHH:MM:SSZ`.
- `rights` is one of the rights identifiers declared in `FORMAT.md` for that particular edition.
- `version_doi` identifies this *specific* edition, not the evolving concept. `arxiv_version` includes a `vN` suffix and should refer to the registered arXiv version. ISBN-13 values are assigned separately for EPUB, PDF and print **when those formats qualify for ISBN registration**. An OCLC number identifies a bibliographic record and may not map one-to-one to a particular manifestation.
- ISBN-13, ISSN and ORCID/ISNI checksums are verified. An assigned ISBN must not be reused for another format or edition in this index.

Example with placeholders (illustration only, **not a valid registry entry until populated**):

```json
{
  "artifact_sha256": "<SHA-256 of official release asset>",
  "canonical_artifact": "sample-work-v1.0.0.html",
  "published_at": "<actual UTC release time>",
  "release_url": "https://github.com/nashspence/press/releases/tag/works/sample-work/v1.0.0",
  "rights": "all-rights-reserved",
  "schema": "press.edition-registration.v1",
  "version": "v1.0.0",
  "work": "sample-work"
}
```

After publication, copy the template into the correct registration path, fill the actual release data, and optionally add a nested `identifiers` mapping. Don't populate future edition records prematurely. This registration is **not** the act of publication; see `PUBLICATION.md`.

### Author, imprint and serial identity

Identity records require `schema: "press.identity.v1"`, `type: "author"` or `"imprint"`, `name`, and a nonempty `identifiers` map. File name and `type` must agree. These are for legitimately assigned *creator or publisher* identifiers, not publication IDs. ORCID in a manuscript is optional and links the author to that work; the identity record is a broader bibliographic index.

Series records require `schema: "press.series.v1"`, `slug`, `title` and nonempty `identifiers` (e.g. an assigned ISSN); the filename must match the slug. **An imprint is not automatically a serial** and must not use an ISSN merely because it publishes multiple works.

## Identifier normalization and limits

- DOI: bare lowercase `10.prefix/suffix`; neither URL nor prefixed `doi:`. DOI comparison is case-insensitive, so lowercase is the convention here.
- OpenAlex: bare uppercase `W` (works), `A` (authors) or `P` (publishers), followed by decimal digits. Wikidata: `Q` followed by decimal digits.
- ORCID: hyphenated `0000-0000-0000-0000` with MOD 11-2 checksum (final character may be `X`); ISNI: four groups separated by spaces and a corresponding checksum.
- arXiv: base ID without `arXiv:` prefix or `vN`; `arxiv_version` adds the explicit version suffix. Legacy subject-class IDs are supported.
- ISBN-13: bare thirteen digits, 978/979 prefix, valid check digit. ISSN/ISSN-L: `NNNN-NNNC` with MOD 11 check digit. OCLC: bare nonzero decimal integer.

A syntactically valid value can still be unassigned, misattributed, withdrawn, merged or reassigned in a remote catalogue. Registry verification remains an **editorial** requirement. A future release process should verify external registrations and the release asset digest before updating the public catalog; the source checker does not issue registry IDs or publish releases.
